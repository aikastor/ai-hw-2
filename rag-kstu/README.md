# Чат-помощник КГТУ — запуск через Docker

Приложение отвечает на русском и английском по проверенным официальным материалам КГТУ и показывает ссылки на источники. FastAPI, Streamlit и Ollama запускаются в контейнерах. Qdrant работает внутри API и хранит индекс в отдельном Docker volume. Groq генерирует и проверяет ответы: выбранные фрагменты источников и сообщения диалога передаются внешнему сервису.

## Что нужно преподавателю

- Установленный и запущенный **Docker Desktop** на macOS/Windows либо Docker Engine с Compose на Linux.
- Собственный ключ **Groq API** и интернет для скачивания образов, модели и генерации ответов.
- Достаточно свободной памяти и диска для Docker, Python-зависимостей и модели bge-m3. Сама модель занимает около 1,2 ГБ; образ Ollama добавляет несколько гигабайт. Нужен дополнительный запас места для остальных образов и сборки. Для первого запуска разумно выделить Docker 8 ГБ памяти, но это рекомендация, не измеренный минимум.

Python и Ollama на основной системе устанавливать не нужно. Docker всё равно использует ресурсы компьютера; это не облачный хостинг. По умолчанию модель работает на CPU, без настройки GPU.

## Первый запуск

```sh
git clone https://github.com/aikastor/ai-hw-2.git
cd ai-hw-2
cp rag-kstu/.env.example rag-kstu/.env
```

В Windows PowerShell вместо `cp` можно использовать:

```powershell
Copy-Item rag-kstu/.env.example rag-kstu/.env
```

Откройте `rag-kstu/.env` и замените значение `GROQ_API_KEY` своим ключом. Остальные настройки можно оставить без изменений. Этот файл игнорируется Git и исключён из контекста сборки Docker. Ключ передаётся только контейнеру API, не интерфейсу и не Ollama.

Запустите из корня репозитория:

```sh
docker compose up --build
```

На первом запуске Docker скачает образы, установит зависимости, загрузит закреплённую модель bge-m3 и создаст индекс из 69 сохранённых фрагментов. Это может занять несколько минут. Повторно собирать сайт, делать OCR или разбивать документы не требуется. Интерфейс запускается после готовности API.

Откройте **http://localhost:8501**. Проверка API: http://localhost:8000/health. Описание запросов: http://localhost:8000/docs.

## Остановка и повторный запуск

Для остановки нажмите **Ctrl+C** в терминале. Либо запустите в другом терминале:

```sh
docker compose down
```

Модель и индекс сохранятся. Для повторного запуска:

```sh
docker compose up
```

Для работы в фоне:

```sh
docker compose up --build -d
docker compose ps
docker compose logs -f api
```

Не используйте `docker compose down -v` для обычной остановки: этот флаг удаляет сохранённые модель и индекс.

## Проверка работы

Попробуйте:

- Какие программы бакалавриата есть в КГТУ?
- Какие документы нужны для поступления после 11 класса?
- Как рассчитывается GPA?
- На какой срок можно взять академический отпуск?

[Набор вопросов на русском](evaluation/validation-ru.md) содержит ожидаемые ответы и проверки отказов. Это план проверки, а не гарантия прохождения каждого теста. Кнопка **Reset conversation** очищает историю.

В контейнере можно выполнить тесты чата и проверить исходные фрагменты:

```sh
docker compose exec api python -m unittest discover -s rag-kstu/scripts -p test_chat.py
docker compose exec api python rag-kstu/scripts/expanded_sources.py validate
```

Не запускайте отдельный Retriever против занятой работающим API базы: локальная Qdrant допускает только одного владельца хранилища.

## Если не запускается

- **Docker daemon недоступен:** запустите Docker Desktop.
- **Порт 8000 или 8501 занят:** остановите прежний локальный запуск. В качестве альтернативы задайте `KSTU_API_PORT` и `KSTU_UI_PORT` в окружении перед запуском Compose.
- **Долго нет интерфейса:** проверьте `docker compose logs -f api ollama`. Первая загрузка модели и построение индекса требуют времени.
- **API не становится healthy:** проверьте ключ Groq и доступ к интернету. После изменения `.env` выполните `docker compose up --build --force-recreate`.
- **Недостаточно памяти:** увеличьте доступную Docker память и повторите запуск. На CPU обработка может быть медленной.
- **Не совпадает версия модели или данные индекса:** приложение останавливается, не подменяя модель и не стирая базу автоматически. Сохраните журнал ошибки перед пересозданием данных.

Groq ограничивает частоту запросов. Ответ проходит два обращения к модели — генерацию и проверку. Ошибка сервиса не означает отсутствие университетской информации.

После изменения кода или промптов выполните `docker compose up --build`. Исходники копируются в образ; обычного перезапуска контейнера для их обновления недостаточно.

## Устройство и данные

- `ollama`: закреплённый образ версии 0.40.6 и модель bge-m3 с проверкой digest; хранилище `ollama-models`.
- `api`: проверяет модель и источник данных, создаёт или проверяет индекс в `retrieval-index`, запускает FastAPI с одним worker.
- `ui`: Streamlit обращается к API по внутренней сети Docker.

Порты интерфейса и API опубликованы только на localhost. Ollama доступен внутри сети Compose и не публикует порт на компьютере.

Каталоги `rag-kstu/data/` и `data/` содержат фрагменты, исходные документы и результаты извлечения, необходимые для проверки происхождения информации. Сохраняйте оба каталога. Модель, сгенерированная база, секреты и виртуальные окружения в Git не входят.

Каталог включает бакалавриат и специалитет; квалификации нельзя смешивать. Некоторые положения опубликованы в 2025 году, а центральный список документов не имеет даты действия. Общеуниверситетские пороги ОРТ и квоты грантов на бакалавриат на 2026–2027 год ещё не подтверждены. Стоимость представлена для выбранных институтов и категорий студентов.

Подробнее: [манифест источников](data/expanded/source-manifest.json), [атрибуция документов](ATTRIBUTION.md). Исторические отчёты могут относиться к предыдущим версиям. Оценка Ragas и защита проекта остаются отдельным этапом.

## Что проверено для Docker

На Docker Desktop с Linux ARM64 образ приложения успешно собран. В контейнере прошли 35 тестов чата, 9 тестов подготовки модели/индекса и 4 теста разрешённых адресов Ollama. Проверены все 69 фрагментов и HTTP health-интерфейса Streamlit. Проверено, что `.env` не попал в образ.

Полный первый запуск всех трёх сервисов с загрузкой Ollama и модели пока не завершён: загрузка большого образа Ollama ещё продолжается. Полный запуск, ответ чата и сохранение индекса после перезапуска ещё не подтверждены. Windows и Linux AMD64 отдельно не запускались.

## Проверка экспорта

`package_repository.py` создаёт отдельный репозиторий из разрешённого набора файлов. `verify_package.py` сверяет экспорт с `PACKAGE-INVENTORY.json`. После осознанного изменения файлов инвентарь необходимо обновить. Он проверяет исходный пакет, а не сгенерированные Docker volumes.

Справка по использованным механизмам: [порядок запуска Docker Compose](https://docs.docker.com/compose/how-tos/startup-order/) и [Ollama в Docker](https://docs.ollama.com/docker).
